# Change Management

## Proposing a Change
1. Create a new ADR: `spec-kit/adr/0004-<short-name>.md`
2. Fill in Status: `Proposed`
3. Tag the affected phase(s)
4. Request review from the architecture owner

## Approving a Change
- ADR moves to `Accepted` only after sign-off.
- Implementation may not begin until accepted.
- If implementation deviates from the ADR, file a new ADR or update the existing one.

## Deprecating
- Move ADR to `Deprecated` and link to its replacement.

## Emergency Changes
- Security incidents may bypass the ADR process with verbal approval.
- A retrospective ADR must be filed within 2 business days.
